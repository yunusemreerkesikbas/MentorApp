The approved SMS implementation is present on `codex/sms-otp-completion`, based on
`2cd6069d` plus the current overlay. This completion adds the durable account-erasure fence,
stabilizes browser checks, updates integration fixtures for verified contacts and explicit
purchase intent, and defers the shared paywall's SMS interface until it opens. Existing user
changes in study-session, join-room, navigation and history views are preserved.

responses. Browser tests use the existing local web server on port 3000 with mocked API
responses at 375 x 812 and 1280 x 800. They establish interface behavior, not live delivery
or real payment acceptance. No production migration, SMS delivery, payment or deployment ran.

## Netgsm follow-up documentation review

After the user merged completion PR #138, this follow-up uses `codex/netgsm-doc-review` from
`546dcd90`. The rendered [official OTP section](https://www.netgsm.com.tr/dokuman/#otp-sms)
was compared directly with the adapter. The request and response contract matches. One gap
was reproduced with three failing tests: Netgsm-enabled startup allowed a sender shorter than
three characters. The missing minimum is now enforced; disabled SMS still permits an empty sender.

Fresh verification: five focused unit files, 80/80 tests passed (21 transport, seven phone env,
48 existing env, three phone crypto and one phone input); API typecheck and scoped ESLint passed.
Transport tests assert Basic Auth uses the subscriber number and API subuser password, exact JSON
fields, both configured message lifetime bounds, long string task IDs, rejection/unknown outcomes,
non-2xx HTTP responses and real abort-signal expiry without a second call. All network responses
are injected; no live Netgsm request or delivery pilot ran. These checks do not replace full CI
before merging this follow-up.
